Lab House

Alonzo's homelab, as a house

A beginner's study guide to my homelab. The server is a house, and every program is a room or a worker. Tap a room to see what it does. Any underlined word explains itself when you tap it.

Start here: never heard of a homelab?
1What's a homelab?

Your own mini data center at home: a computer that runs 24/7 so you can practice the same things IT and security pros do at work, without breaking anything important.

A $40 used thin client in my room running ad blocking, a VPN, monitoring, and an attack blocker.

2What's a server?

A computer whose job is to serve things to other devices, all day, usually with no screen or keyboard. "Server" describes the job, not a special kind of machine.

My Dell Wyse 5060 sits in a corner with no monitor. My phone and laptop use what it serves.

How did my server get there?

The Wyse didn't come as a server. It was a thin client: a small office computer built to be a "dumb screen" that logs into a bigger computer somewhere else. It shipped with Dell's own locked-down system. Businesses replace them in bulk, so they sell used for cheap. That made it a great first server: quiet, tiny, and low on power.

The journey, step by step:

  1. Got the hardware. A used Wyse 5060, about $40.
  2. It came with Debian already on it. The seller had replaced Dell's system with Debian 12 Linux before selling it.
  3. Took over as admin. I logged in with a monitor and keyboard. Now it's my machine, and I can install anything.
  4. Connected it to the network. An ethernet cable runs from the Wyse to my wall-plug Wi-Fi extender, which links it to my router, so other devices can reach it.
  5. Turned on remote control. I set up SSH (control by typing from my laptop or phone) and later Tailscale (reach it from anywhere).
  6. Went headless. I unplugged the monitor and keyboard. Now it sits in a corner and I run everything remotely.
  7. Moved in the workers. Docker, Pi-hole, Unbound, Jellyfin, Uptime Kuma, CrowdSec, Dozzle, and the dashboard.
Used thin client→Debian pre-installed→Ethernet to extender→SSH + Tailscale→Headless server ✅

Analogy: buying an old storefront and turning it into a restaurant. The building came empty (the hardware). The seller already gutted it and hired a manager (Debian came pre-installed). Plugging into the network is getting a street address. SSH and Tailscale are the back door and a phone line, so I can run things without standing inside. Then the cooks move in (the programs).

Security note: since the seller installed Debian, it isn't a build I can fully trust. That's supply-chain risk: like a used house, you don't know who kept a copy of the keys. The fix is to reinstall from debian.org (change every lock) or audit the users, SSH keys, and startup jobs (check every door).

3What runs on it?

Three layers stacked on each other: the hardware, an operating system (Linux), and programs on top. Some programs run silently in the background (services). Others run in sealed boxes (Docker containers) and have a web page you open in a browser.

Pi-hole is a program. Its dashboard is a web page served by the Wyse, not a website on the internet.

Analogy: the hardware is a restaurant building and its kitchen equipment. The operating system is the manager who runs the place. Programs are the cooks and staff, each with one job.

Layer 1: hardware (the physical stuff)

The parts you can touch. The CPU does the thinking, RAM is short-term memory (wiped when power goes off), the drive is long-term storage, and the network port connects it to everything else.

The Wyse: a small CPU, a few GB of RAM, a tiny 6.4GB internal drive, plus my 1.8TB external drive for the big stuff.

Hardware alone does nothing. It needs software telling it what to do.

Layer 2: what an operating system is

The operating system (OS) is the main software that boots first and manages the hardware for everyone else. It decides which program gets the CPU, hands out memory, saves files to the drive, talks to the network, and keeps programs from messing with each other.

Without an OS, every app would have to know how to control the exact hardware it's on. The OS hides all that, so programs just ask "save this file" or "send this over the network."

Windows on most laptops, macOS on Macs, iOS on iPhones, Android on most other phones, and Linux on the Wyse.

So what is Linux?

Linux is a free, open-source operating system. "Open source" means anyone can read and change its code, so companies and volunteers all over the world improve it.

Strictly, "Linux" is the kernel: the core that talks directly to the hardware. A full system bundles that kernel with tools, a package manager, and settings. That bundle is a distribution (distro). There are many flavors that share the same core.

Debian 12 (the Wyse), Ubuntu, Kali (built for hacking practice), Fedora, and the Linux inside Android and most smart TVs.

Why servers run Linux: it's free, it's light enough for tiny machines like the Wyse, it runs for months without a reboot, and it's controlled entirely by typing commands, which is perfect for managing it remotely over SSH. Most of the internet, the cloud, and supercomputers run Linux, so SOC analysts read Linux logs all day.

How you use it: mostly through the terminal (command line). You type a command, press Enter, and it runs.

df -h shows disk space. sudo apt install crowdsec installs a program. sudo means "do this as the admin."

Layer 3: what a program actually is

A program is a file full of instructions for the computer. Sitting on the drive, it's just a file, like a recipe in a cookbook. When you start it, the OS loads it into RAM and the CPU follows the instructions. A running program is called a process, the cook actually cooking.

Pi-hole is files on the drive. When the Wyse boots, it starts, and now it's a process answering DNS questions.

Where programs come from: on Linux you install them with a package manager, which works like an app store you control by typing.

sudo apt install unbound downloaded and installed Unbound on the Wyse.

Where programs come from: the package manager

Is it built in? Yes. On Debian the package manager is called apt, and it came with the operating system, like the App Store comes pre-installed on an iPhone. It's a program itself.

Where the programs live: on the internet, on servers called repositories (repos). Debian runs its own repos holding tens of thousands of programs, already pre-built by volunteers called package maintainers. Each ready-to-install program is a package.

apt = the App Store app. The repository = Apple's warehouse online. A package = one app in the warehouse. The Wyse's list of trusted warehouses is the file /etc/apt/sources.list.

What happens when you install something:

1. sudo apt update downloads the latest catalog (what's available). Nothing installs yet.
2. sudo apt install unbound finds it in the catalog and figures out what else it needs to run (its dependencies, like batteries a toy needs).
3. It downloads everything from the repo over the internet.
4. It checks Debian's digital signature. If anything was tampered with, it refuses to install.
5. It puts the files in the right folders and sets it up as a service.

Not everything comes from Debian. Some companies run their own repo. You add it to the trusted list, then apt can install from it.

The CrowdSec install script added CrowdSec's repo, then sudo apt install crowdsec pulled from it. Tailscale works the same way.

Security idea: adding a repo means trusting that company to put software on your server as admin. That's supply-chain trust: only add repos from official sources.

Docker apps are different: containers come from image registries like Docker Hub, not apt. Same idea, a warehouse of pre-built apps online, but docker compose up -d does the downloading.

The 3 kinds of programs in my lab

1. Commands you run once. They do one job, print a result, and stop.

df -h, ls, docker ps.

2. Services, also called daemons. Programs that start when the computer boots and run in the background forever, waiting for work. No window, no screen. Linux's systemd starts them and restarts them if they crash.

SSH waits for logins, Tailscale keeps the tunnel up, Unbound waits for lookups, CrowdSec watches logs. Check one with systemctl status ssh.

3. Containers (Docker). A program packed into a sealed box with everything it needs: its own files, settings, and pieces. It runs the same anywhere and can't trash the rest of the system. Like a shipping container: the ship doesn't care what's inside.

Pi-hole, Jellyfin, Homepage, and Uptime Kuma each run in their own container. docker ps lists them.

Why some programs have a web page

Programs with no screen still need a way for you to control them. Many include a tiny built-in web server, so you open their control panel in any browser instead of installing an app. The Wyse serves the page; your phone just displays it.

The port picks which program answers: same address, different door.

:80 = Pi-hole, :8096 = Jellyfin, :3000 = Homepage, :3001 = Uptime Kuma. SSH, Unbound, and CrowdSec have no web page: you use them by typing commands.

4How do I reach it?

Every device has an address (an IP). Each program on the server listens on its own numbered door (a port). Address + port = which program you're talking to.

100.119.39.63:3000 = the Wyse, door 3000 = my dashboard.
